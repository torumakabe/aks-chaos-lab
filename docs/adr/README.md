# Architecture Decision Records (ADR)

このディレクトリには、プロジェクトの設計判断を個別に記録した ADR を格納する。

## ADR とは

ADR は「なぜそうなっているか」を記録するドキュメント。コードは「何を作ったか」を示すが、「何を却下し、なぜその選択をしたか」は示さない。ADR がその隙間を埋める。

## フォーマット

```markdown
# ADR-NNN: タイトル

## Status
Accepted / Rejected / Superseded by ADR-NNN / Deprecated

## Context
何が問題だったか（2-3行）

## Decision
何を選び、何を却下したか（理由付き）

## Consequences
この判断の結果、何が楽になり、何が制約になるか
```

## 判断の変更と Status

判断を変更するときは、対象が旧 ADR の判断全体か一部かを確認する。

| 対象と変更 | 旧 ADR の Status 節の表記 |
|---|---|
| 一部を後続の判断で変更し、有効な判断が残る | `Accepted` を維持し、変更範囲、残る有効な判断、後続 ADR へのリンクを注記する |
| 全体を後続の判断で置き換える | `Superseded by ADR-NNN` にし、後続 ADR へリンクする |
| 後継なしで一部を廃止し、有効な判断が残る | `Accepted` を維持し、廃止範囲と残る有効な判断を注記する |
| 後継なしで全体を廃止する | `Deprecated` にする |

旧判断の本文は履歴として残す。後続 ADR には旧 ADR へのリンク、変更範囲と理由を記載し、廃止理由は旧 ADR の Context または Consequences に記録する。説明の明確化だけで判断が変わらない場合は、置換として扱わない。新規 ADR の要否は次節の作成と更新の基準で判断する。

INDEX の Status は基本 Status の要約であり、一部変更の注記をすべて転記する必要はない。適用範囲は各 ADR 本文の Status 節と、そこから参照する後続 ADR で確認する。

## 作成と更新の基準

次の3条件をすべて満たす判断だけを ADR に記録する。

1. **有力な代替案の却下、または外部制約がある**：標準的な別案を意図的に選ばなかった、あるいは非互換やサービス仕様などの制約で選べなかった。
2. **コードや現行文書だけでは誤変更を防げない**：実装を見ても別のやり方を選ばなかった理由が分からず、将来の開発者や AI エージェントが意図に反する変更をしてしまうおそれがある。
3. **複数領域にまたがる、またはやり直しコストが高い**：インフラ再作成、監視設計の変更、開発ワークフロー全体の変更など、後から覆す影響が大きい。

### ADR にしないものと置き場所

| 内容 | 代わりの置き場所 |
|---|---|
| 撤去条件のある一時的な回避策 | [docs/workarounds.md](../workarounds.md) とコードコメント |
| 現行の操作手順、既定値、フラグの切り替え | `docs/deployment.md` などの運用文書 |
| 移行完了後の片付け、不要スクリプトの削除 | Pull Request の説明とコミット履歴 |
| 1箇所で完結する数値や設定の理由（SKU、CIDR、タイムアウトなど） | コードコメント |
| 既存 ADR に対する細則の追加や小調整 | 該当する運用文書。判断の前提が変わった場合だけ新規 ADR または統合 |

判断ごとに短くまとめ、必要な理由、却下した選択肢、制約を残す。実装手順や検証ログは ADR に含めない。

### 採番、統合、レビューのルール

- **採番と索引の整合**：新規作成時は [INDEX.md](INDEX.md) と実際の ADR ファイルを照合し、重複しない次の番号を選ぶ。番号や対応が崩れている場合は、採番前に差異を解消する。
- **`amend` 連鎖の防止**：同じ領域で一部変更が2回以上重なった場合は履歴を継ぎ足さず、現行判断を1本の ADR に統合して旧 ADR 群をまとめて `Superseded` にする。
- **レビュー時の判断軸**：実装と ADR の不一致を見つけた場合は、実装側の逸脱か、未記録の判断変更かを区別する。コードが変わったことだけを理由に ADR を廃止しない。
- **不採用（`Rejected`）の扱い**：`Rejected` は「採用しない」という現在も有効な判断であり、再提案を防ぐ根拠として参照対象に残す。
