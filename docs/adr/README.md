# Architecture Decision Records (ADR)

このディレクトリには、プロジェクトの設計判断を個別に記録した ADR を格納する。

## ADR とは

ADR は「なぜそうなっているか」を記録するドキュメント。コードは「何を作ったか」を示すが、「何を却下し、なぜその選択をしたか」は示さない。ADR がその隙間を埋める。

## フォーマット

```markdown
# ADR-NNN: タイトル

## Status
Accepted / Rejected / Superseded by ADR-NNN / Deprecated

## Context
何が問題だったか（2-3行）

## Decision
何を選び、何を却下したか（理由付き）

## Consequences
この判断の結果、何が楽になり、何が制約になるか
```

## 判断の変更と Status

判断を変更するときは、対象が旧 ADR の判断全体か一部かを確認する。

| 対象と変更 | 旧 ADR の Status 節の表記 |
|---|---|
| 一部を後続の判断で変更し、有効な判断が残る | `Accepted` を維持し、変更範囲、残る有効な判断、後続 ADR へのリンクを注記する |
| 全体を後続の判断で置き換える | `Superseded by ADR-NNN` にし、後続 ADR へリンクする |
| 後継なしで一部を廃止し、有効な判断が残る | `Accepted` を維持し、廃止範囲と残る有効な判断を注記する |
| 後継なしで全体を廃止する | `Deprecated` にする |

旧判断の本文は履歴として残す。後続 ADR には旧 ADR へのリンク、変更範囲と理由を記載し、廃止理由は旧 ADR の Context または Consequences に記録する。説明の明確化だけで判断が変わらない場合は、置換として扱わない。新規 ADR の要否は次節の粒度の基準で判断する。

INDEX の Status は基本 Status の要約であり、一部変更の注記をすべて転記する必要はない。適用範囲は各 ADR 本文の Status 節と、そこから参照する後続 ADR で確認する。

## 粒度の基準

**「6ヶ月テスト」**: 6ヶ月後に別の人（または自分）が「なぜこうなっている？変えていい？」と聞くか？
- 聞かれそうなら → ADR にする
- 聞かれなさそうなら → 不要（コードや instructions で十分）

**ADR にするもの**: 別の選択をする合理的な理由があった判断
**ADR にしないもの**: 一時的な判断（SKU 選定）、影響の小さい技術的詳細（CIDR レンジ）

判断ごとに短くまとめ、必要な理由、却下した選択肢、制約を残す。実装手順や検証ログは ADR に含めない。

ADR の作成、廃止、置換、非編集レビューの手順は [manage-adr](../../.github/agents/manage-adr.agent.md) を参照する。
